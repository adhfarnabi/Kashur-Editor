## 1. Project Structure

```
kashur-editor-backend/
│
├── server.js                 ← Express entry point, MongoDB connect, route mounting
│
├── .env                      ← YOUR secrets (never commit this to git)
├── .env.example              ← Template — copy to .env and fill in
├── package.json
│
├── models/
│   ├── User.js               ← User schema: name, email, password(hashed), OTP fields

│
├── routes/
│   ├── auth.js               ← signup, verify-otp, login, forgot-password, reset-password
│   └── documents.js          ← CRUD + export + share toggle (all protected by JWT)
│
├── middleware/
│   └── auth.js               ← protect() — reads JWT, verifies, attaches req.user

│
└── utils/
    ├── jwt.js                ← generateToken(userId), verifyToken(token)
    └── email.js              ← sendEmail(), OTP email HTML templates
```

## 2. Setup & Run

### Step 1 — Install dependencies
```bash
cd kashur-editor-backend
npm install
```

### Step 2 — Configure environment
```bash
cp .env.example .env
```
Open `.env` and fill in all values (see section 3 below).

### Step 3 — Start MongoDB

**Local:**
```bash
mongod
# OR on Mac with Homebrew:
brew services start mongodb-community
```

**MongoDB Atlas (cloud):** Just set `MONGO_URI` in `.env` — no local install needed.

### Step 4 — Run the server
```bash
npm run dev        # development (auto-restarts on file change, needs nodemon)
npm start          # production
```

**Expected output:**
```
✅  MongoDB connected: mongodb://127.0.0.1:27017/kashur_editor
🚀  kashur Editor API → http://localhost:3001
```

### Step 5 — Test it's alive
Open browser or Postman: `GET http://localhost:3001/api/health`

Expected response:
```json
{
  "status": "ok",
  "time": "2024-01-15T10:30:00.000Z",
  "database": "connected"
}
```

## 4. Database Schema

### User Collection

| Field | Type | Notes |
|-------|------|-------|
| `_id` | ObjectId | Auto-generated by MongoDB |
| `name` | String | Min 2 chars, required |
| `email` | String | Unique, lowercase, required |
| `phone` | String | Optional |
| `password` | String | Bcrypt hashed (never returned in API) |
| `emailVerified` | Boolean | Default: false. Must be true to login |
| `otp` | String | SHA-256 hash of OTP (never plain text in DB) |
| `otpExpiry` | Date | 10 minutes from generation |
| `otpPurpose` | String | `"verify"` or `"reset"` |
| `otpAttempts` | Number | Increments on wrong guess, locked at 5 |
| `passwordChangedAt` | Date | Used to invalidate old tokens after password change |
| `active` | Boolean | Default: true. False = account disabled |
| `createdAt` | Date | Auto (timestamps) |
| `updatedAt` | Date | Auto (timestamps) |

### Document Collection

| Field | Type | Notes |
|-------|------|-------|
| `_id` | ObjectId | Auto-generated |
| `title` | String | Default: "Document 1", max 500 chars |
| `html` | String | Full HTML content of the document |
| `userId` | ObjectId | References User._id. Every document belongs to one user |
| `wordCount` | Number | Auto-calculated on save |
| `pageCount` | Number | Number of A4 pages |
| `isPublic` | Boolean | Default: false. true = anyone with shareToken link can view |
| `shareToken` | String | 64-char crypto-random hex. null when private |
| `deletedAt` | Date | null = active, Date = soft deleted (not shown in lists) |
| `createdAt` | Date | Auto |
| `updatedAt` | Date | Auto |

## 5. How Authentication Works

```
1. User signs up → POST /api/auth/signup
   Backend creates user (emailVerified=false) → generates 6-digit OTP
   → hashes OTP with SHA-256 → saves to DB → sends plain OTP to email

2. User enters OTP → POST /api/auth/verify-otp
   Backend hashes entered OTP → compares with stored hash
   → if match: emailVerified=true, password hashed & saved
   → returns JWT token (7 day expiry)

3. All document requests need JWT in header:
   Authorization: Bearer <token>

4. protect() middleware in every document route:
   - Reads token from Authorization header
   - Calls jwt.verify(token, JWT_SECRET)
   - Finds user in DB by decoded ID
   - Checks passwordChangedAt (invalidates stale tokens)
   - Attaches req.user to the request

5. Every document query filters by req.user._id:
   { userId: req.user._id, deletedAt: null }
   → users ONLY see their own documents
```

## 6. Postman Setup

### Create a Collection

1. Open Postman
2. Click **New Collection** → name it `kashur Editor API`
3. Add a **Collection Variable** called `token` (leave value empty for now)
4. Add a **Collection Variable** called `baseUrl` = `http://localhost:3001`
5. Add a **Collection Variable** called `docId` (leave empty for now)

### Set Token Automatically After Login

In the **Login** request → **Tests** tab, paste:
```javascript
if (pm.response.code === 200) {
    const data = pm.response.json()
    pm.collectionVariables.set("token", data.token)
    console.log("Token saved:", data.token.slice(0, 20) + "...")
}
```
This saves the token automatically after every successful login or OTP verify.

### Authorization Header Setup

For all protected requests, in the **Authorization** tab:
- Type: `Bearer Token`
- Token: `{{token}}`

OR in the **Headers** tab:
- Key: `Authorization`
- Value: `Bearer {{token}}`

**No auth required.**

```json
{
    "message": "Account created! Please check your email for the OTP verification code.",
    "email": "addu@example.com",
    "action": "verify"
}
```

**Test Cases in Postman:**

| Test | Change in body | Expected status | Expected response |
|------|---------------|-----------------|-------------------|
| Normal signup | Use fresh email | 201 | message + action:"verify" |
| Missing name | Remove "name" | 422 | error: "Name must be at least 2 characters" |
| Invalid email | email: "notanemail" | 422 | error: "Valid email is required" |
| Weak password | password: "abc" | 422 | error: "Password must be at least 8 characters" |
| No uppercase | password: "mypass123" | 422 | error: "...uppercase letter" |
| No number | password: "MyPassword" | 422 | error: "...number" |
| Passwords mismatch | confirmPassword: "Different1" | 422 | error: "Passwords do not match" |
| Already registered | Same email again | 409 | code: "ALREADY_REGISTERED" |

### 7.2 — Verify OTP (Email Verification)
`POST /api/auth/verify-otp`

**No auth required.**

After signup, check your email for the 6-digit OTP. If no email (dev mode), check the server console — the OTP is printed there.

**Request Body:**
```json
{
    "email": "addu@example.com",
    "otp": "123456"
}
```

**Success Response (200):**
```json
{
    "message": "Email verified successfully! Welcome.",
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "user": {
        "id": "65a1b2c3d4e5f6789...",
        "name": "Adhfar Nabi",
        "email": "addu@example.com",
        "phone": "+92 300 1234567",
        "emailVerified": true,
        "createdAt": "2024-01-15T10:00:00.000Z"
    }
}
```

**In Postman Tests tab — auto-save token:**
```javascript
if (pm.response.code === 200) {
    pm.collectionVariables.set("token", pm.response.json().token)
}
```

**Test Cases:**

| Test | Body | Expected |
|------|------|----------|
| Correct OTP | Real OTP from email/console | 200 + token |
| Wrong OTP | otp: "000000" | 400, code: "OTP_WRONG", attemptsLeft: 4 |
| Wrong OTP 5 times | otp: "000000" x5 | 429, code: "OTP_LOCKED" |
| Expired OTP | Wait 10 minutes | 400, code: "OTP_EXPIRED" |
| Already verified | Verify again | 400, "Email already verified" |

---

### 9.1 — Toggle Share (Make Public or Private)
`PATCH /api/documents/:id/share`

**Requires JWT.** Only the document owner can toggle.

**Make Public:**
```json
{
    "isPublic": true
}
```

**Success Response — Public (200):**
```json
{
    "id": "65a1b2c3d4e5f678901234",
    "isPublic": true,
    "shareToken": "a3f8b2c1d4e5f6789012345678901234abcd5678ef012345678901234567890ab",
    "shareUrl": "http://localhost:5173/view/a3f8b2c1d4e5f6789012345678901234abcd5678ef012345678901234567890ab"
}
```

**Make Private:**
```json
{
    "isPublic": false
}
```

**Success Response — Private (200):**
```json
{
    "id": "65a1b2c3d4e5f678901234",
    "isPublic": false,
    "shareToken": null,
    "shareUrl": null
}
```

**Note:** When made private, the old shareToken is **permanently deleted**. If made public again, a completely new token is generated. Old shared links immediately stop working.

**Test Cases:**

| Test | Expected |
|------|----------|
| Make public (first time) | 200 + new shareToken + shareUrl |
| Make public again | 200 + same shareToken (not regenerated) |
| Make private | 200 + shareToken: null |
| Make public after private | 200 + NEW different shareToken |
| Missing isPublic | 422 |
| Another user's document | 404 |

## 11. Common Errors & Fixes

### ❌ `TypeError: next is not a function`
**Cause:** Using `async` with `next` in Mongoose middleware.
```js
// WRONG
UserSchema.pre("save", async function (next) { ... next() })

// CORRECT
UserSchema.pre("save", async function () { ... })
```

### ❌ `ETIMEDOUT :465`
**Cause:** Using `service: "gmail"` forces port 465 which many networks block.
```js
// WRONG
nodemailer.createTransport({ service: "gmail" })

// CORRECT
nodemailer.createTransport({ host: "smtp.gmail.com", port: 587, secure: false })
```

### ❌ `MongoDB connection failed: ECONNREFUSED`
**Cause:** MongoDB is not running.
```bash
mongod          # start local MongoDB
# OR
brew services start mongodb-community   # Mac
```

### ❌ `Cast to ObjectId failed`
**Cause:** Invalid MongoDB ID passed as URL parameter.
Make sure you're using a real `_id` from a previous response, not a made-up string.

### ❌ `401 Authentication required` on document routes
**Cause:** Missing or wrong Authorization header.
Make sure header is exactly: `Authorization: Bearer eyJhbGci...`
No extra spaces, token must not be expired.

### ❌ `403 EMAIL_NOT_VERIFIED` on document routes
**Cause:** Logged in but never completed OTP verification.
Call `POST /api/auth/verify-otp` with the correct OTP first.

### ❌ `CORS blocked` in browser
**Cause:** Your frontend URL is not in the allowed origins list.
Add your URL to `.env`:
```
FRONTEND_URL=http://localhost:3000
```

### ❌ OTP not arriving in email
**Cause:** Wrong Gmail credentials or App Password.
- Check MAIL_USER and MAIL_PASS in `.env`
- App Password must be the 16-char one from Google Account → Security → App Passwords
- **Dev tip:** If no email config, OTP is printed to the server console automatically

### ❌ `501 DOCX export requires the 'docx' package`
```bash
cd kashur-editor-backend
npm install docx
node server.js    # restart required
```

## Quick Test Sequence in Postman

Follow this order to test the full flow from scratch:

```
1.  GET  /api/health                              → confirm server running
2.  POST /api/auth/signup       { name, email, password, confirmPassword }
3.  POST /api/auth/verify-otp   { email, otp }    → saves token
4.  GET  /api/auth/me                             → confirm logged in
5.  POST /api/documents         { title, html }   → saves docId
6.  GET  /api/documents                           → list documents
7.  GET  /api/documents/{{docId}}                 → get one
8.  PUT  /api/documents/{{docId}} { title, html } → update
9.  PATCH /api/documents/{{docId}}/share { isPublic: true }  → get shareUrl
10. GET  /api/share/:shareToken                   → test public view (no token)
11. PATCH /api/documents/{{docId}}/share { isPublic: false } → make private
12. GET  /api/share/:sameOldToken                 → confirm 404
13. GET  /api/documents/{{docId}}/export/txt      → download txt
14. GET  /api/documents/{{docId}}/export/docx     → download docx
15. DELETE /api/documents/{{docId}}               → delete
16. GET  /api/documents/{{docId}}                 → confirm 404
17. POST /api/auth/forgot-password { email }      → test password reset
18. POST /api/auth/reset-password  { email, otp, newPassword, confirmPassword }
19. POST /api/auth/login { email, newPassword }   → login with new password
20. POST /api/auth/logout                         → logout
21. POST http://localhost:3001/api/contact        → Contact / Feedback
```
